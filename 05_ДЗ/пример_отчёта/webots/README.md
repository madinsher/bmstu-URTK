# Сцена Webots к примеру отчёта

Мобильный манипулятор youBot выполняет миссию «взять предмет со стола → положить в контейнер → вернуться на базу» под надзором супервизора, синтезированного в [`../des_youbot.py`](../des_youbot.py).

![Сцена](../figures/scene_start.jpg)

## Состав

| Путь | Что это |
|---|---|
| `worlds/youbot_mission.wbt` | мир: база, стол с предметом, контейнер, препятствие |
| `controllers/youbot_mission/youbot_mission.py` | контроллер: навыки, события датчиков, фильтр команд через супервизор, внесение отказов, журнал |
| `controllers/youbot_mission/runtime.ini` | какой Python запускает контроллер — **поправьте путь под свой компьютер** |
| `run_trials.py` | генерация миров под сценарии, пакетные прогоны, сводная таблица |
| `logs/` | журналы прогонов: `*.csv` — события, `*.json` — итог, `*_traj.json` — траектории |
| `logs/video_obstacle.mp4` | видеозапись миссии с объездом препятствия |

## Требования

- Webots **R2025a**;
- Python 3.9+ (контроллер использует только стандартную библиотеку и модуль `controller` из Webots);
- путь к каталогу проекта **без кириллицы и пробелов** — иначе Webots не запускает контроллер. Если репозиторий лежит в папке с русским именем, скопируйте каталог `пример_отчёта` во временную папку.

## Запуск

Открыть мир в Webots и нажать «Пуск» — пойдёт сценарий с препятствием. Сценарий задаётся полем `controllerArgs` робота:

| Аргумент | Значения |
|---|---|
| `scenario` | `nominal`, `obstacle`, `miss`, `slip`, `hasty` |
| `monitor` | `1` — контролировать зазор пальцев при перевозке (выпадение предмета становится наблюдаемым) |
| `sup` | `0` — отключить супервизор (только для сравнения в сценарии `hasty`) |
| `shift` | смещение предмета в сценарии `miss`, м |
| `seed` | случайное смещение предмета на столе |
| `record` | `1` — видео и снимки в `logs/` |

Пакетные прогоны всех сценариев раздела 6 отчёта (без отрисовки, около получаса):

```bash
python run_trials.py trials
```

Сводная таблица по уже накопленным журналам:

```bash
python run_trials.py summary
```

## Как читать журнал

```
t,kind,name,model_state,info
10.336,cmd,a_reach,T/R/O/F/Tb,над столом
12.864,event,a_reached,T/X/O/F/Tb,
```

- `kind`: `cmd` — выданная команда (управляемое событие), `event` — событие от датчиков, `denied` — супервизор запретил команду, `inject` — внесённый отказ, `R1` — нарушение, найденное монитором физики, `fault` — отказ исполнения;
- `model_state` — состояние объекта в модели после события: платформа / манипулятор / захват / восприятие / предмет.

Монитор R1 работает по физике сцены (скорости звеньев и платформы) и от модели не зависит: он ловит и то, что модель «не видит».

## Ограничения сцены

- Позу предмета контроллер берёт из истины сцены — это идеальная система распознавания. Камера с `Recognition` используется только для события «предмет виден». Пример не про точность СТЗ.
- Выпадение предмета вносится переносом предмета на пол, а не физическим срывом.
- Скорость платформы ограничена 0,3 м/с, датчики расстояния настроены на 1 м (раздел 2.6 отчёта).
