# Семинар 6. Планирование задач, геометрия и решения при неопределённости

**После лекций:** 10–12
**Продолжительность:** 2 академических часа

## Цель

Заменить жёстко заданную последовательность действий планировщиком, обеспечить обратную связь от геометрии к символьному уровню, вычислить пороги принятия решений из стоимостей ошибок.

## Что должно получиться

1. Домен PDDL и автоматическая генерация задачи из мировой модели.
2. Работающий цикл «планировать — исполнять — перепланировать» в Webots.
3. Карта достижимости манипулятора и выбор позы базы по обратной карте.
4. Алгоритм перестановки для загороженного предмета.
5. График доли успешных захватов от погрешности позы.
6. Вычисленные пороги уверенности для трёх значений стоимости ошибки.

## Инструменты

- **Fast Downward** — основной планировщик; **pyperplan** — для понимания устройства.
- **OPTIC** или **POPF** — при использовании длительных действий.
- **pomdp-py** или **POMDPs.jl** — решение POMDP.

## Задание 1. Домен PDDL (25 мин)

**1.1.** Опишите домен вашей задачи. Требования:
- 5–10 типов действий; больше — признак избыточной детализации;
- 15–25 предикатов;
- **числовые стоимости обязательны** — иначе оптимизируется длина плана, а не время.

**1.2.** Для каждого действия предусловия и эффекты должны **совпадать** с контрактом навыка из семинара 1. Единое описание исключает рассогласование планировщика и исполнителя.

Заполните таблицу соответствия:

| Действие PDDL | Навык в дереве | pre совпадает? | post совпадает? |
|---|---|---|---|

Расхождения устраните — приведите оба описания к одному.

**1.3.** Предусмотрите предикат «обследовано» отдельно от «объект отсутствует». Предположение о замкнутости мира иначе смешивает отсутствие информации и отсутствие объекта.

**1.4.** Реализуйте **автоматическую генерацию задачи** из текущей мировой модели робота. Задача PDDL не пишется руками — она порождается при каждом перепланировании.

## Задание 2. Планирование и режимы поиска (20 мин)

**2.1.** Запустите Fast Downward в двух режимах: жадный поиск с $h_{FF}$ и A\* с допустимой эвристикой. Сравните время поиска и стоимость плана.

**2.2.** Измерьте время планирования как функцию числа объектов: 2, 4, 8, 16, 32. Постройте график. **Определите, при каком числе объектов планирование перестаёт укладываться в 1 секунду** — это ваш практический предел, и его надо знать до демонстрации.

**2.3.** Вычислите вручную $h_{\max}$ и $h_{\mathrm{add}}$ для начального состояния небольшой задачи. Объясните расхождение.

## Задание 3. Цикл планирования в контуре (25 мин)

**3.1.** Реализуйте цикл:

```
1. Обновить мировую модель по данным восприятия
2. Если план отсутствует или недействителен — построить
3. Проверить предусловие следующего действия
   3a. нарушено → перепланировать
4. Исполнить действие через дерево поведения
5. Проверить постусловие
   5a. не достигнуто → учесть отказ, перепланировать
6. Цель достигнута — завершить, иначе к 3
```

**3.2.** Перепланирование инициируется **событиями**, а не таймером. Перечислите в отчёте события, вызывающие перепланирование в вашей системе.

**3.3.** Внесите отказ (предмет недостижим) и убедитесь в корректном перепланировании. Зафиксируйте: сколько раз система перепланировала за один прогон миссии.

**3.4. Стабильность плана.** Измерьте, насколько меняется план при малом изменении обстановки (добавление одного предмета). Доля изменённых действий — метрика стабильности. Если план меняется целиком — рассмотрите починку плана вместо полного пересчёта.

## Задание 4. Карта достижимости и позиционирование базы (25 мин)

**4.1.** Постройте карту достижимости манипулятора youBot: выборкой по конфигурациям (не менее $10^5$ выборок) заполните воксельную сетку 5 см, для каждого вокселя подсчитайте индекс достижимости. Визуализируйте.

**4.2.** Постройте обратную карту достижимости для захвата сверху: пересчёт в систему координат объекта даёт распределение допустимых поз базы.

**4.3.** Реализуйте выбор позы базы:
```
обратная карта → пересечение с картой проходимости →
сортировка по индексу и стоимости переезда →
проверка ОЗК и коллизий → первый успешный
```

**4.4.** Сравните с наивным подходом «подъехать на фиксированное расстояние»: доля успешных подходов для объектов у стены, в углу, на высоте 0,3 и 1,0 м.

## Задание 5. Обратная связь геометрия → символ (25 мин)

**5.1.** Реализуйте геометрические предикаты как проверки: `reachable(o, l)`, `cfree_traj(t)`, `supported(o, p, s)`.

**5.2.** Реализуйте порождение символьных фактов из результатов проверки. При отказе захвата из-за коллизии порождается `(blocked ?o ?o2)`, и предусловие действия `pick` дополняется требованием отсутствия blocked.

**5.3.** Постройте сцену, где целевой предмет загорожен двумя другими. Убедитесь, что без обратной связи планировщик выдаёт один и тот же неисполнимый план, а с обратной связью — строит план с перестановкой.

**5.4.** Реализуйте алгоритм перестановки с ограничением глубины рекурсии. Выбор позы для перестановки должен учитывать последующие действия, иначе объект будет переставляться многократно.

**5.5.** Сравните два решения: план с перестановкой и план с правильным порядком (загораживающие предметы собираются первыми). Какой дешевле по метрике? Находит ли планировщик второй, если стоимости заданы?

## Задание 6. Робастность к погрешности (20 мин)

**6.1.** Измерьте долю успешных захватов как функцию погрешности оценки позы: 0, 5, 10, 15, 20 мм, по 30 попыток на точку. Постройте график с доверительными интервалами.

**6.2.** Определите допустимую погрешность восприятия для доли успеха 0,9. **Это и есть требование к системе технического зрения**, выведенное, а не назначенное.

**6.3.** Проверьте правило двойного запаса: обеспечивает ли ваш план геометрический зазор не менее удвоенной погрешности по каждому ограничению?

## Задание 7. Пороги принятия решений (20 мин)

**7.1. MDP стратегии захвата.** Постройте MDP с состояниями «поза оценена грубо», «поза уточнена», «в захвате», «поза потеряна», «отказ». Вероятности возьмите **из измерений задания 6**, а не из пособия.

**7.2.** Решите итерацией по ценности. Определите оптимальное действие в начальном состоянии.

**7.3. Анализ чувствительности.** Постройте зависимость оптимального действия от вероятности успеха прямого захвата и от времени уточнения. Найдите пороги переключения стратегии.

**7.4. POMDP распознавания.** Постройте POMDP выбора действия при неуверенной классификации. Матрицу ошибок классификатора измерьте на контрольной выборке (не менее 100 предъявлений).

**7.5.** Вычислите порог уверенности для трёх значений штрафа за ошибочную укладку: $-10, -50, -200$. Сравните с порогом, который вы назначили в контракте навыка на семинаре 1.

**7.6.** Обновите контракт навыка: замените назначенный порог вычисленным. Отразите изменение в матрице трассируемости.

## Критерии приёмки

| Критерий | Требование |
|---|---|
| Домен | pre/post совпадают с контрактами, таблица соответствия заполнена |
| Генерация задачи | автоматическая из мировой модели |
| Предел планирования | измерен, график построен |
| Цикл | работает, перепланирование по событиям, стабильность измерена |
| Карта достижимости | построена, обратная карта используется при выборе позы базы |
| Обратная связь | геометрический отказ порождает символьный факт |
| Перестановка | работает, глубина рекурсии ограничена, дальновидный выбор поз |
| Робастность | график доли успеха от погрешности, выведено требование к СТЗ |
| MDP | вероятности измерены, анализ чувствительности выполнен |
| POMDP | матрица ошибок измерена, три порога вычислены |
| Контракт | порог обновлён, изменение отражено в матрице трассируемости |

## Типовые замечания

1. **Домен и дерево описывают действие по-разному.** Планировщик выдаёт планы, которые исполнитель не может выполнить.
2. **Задача PDDL написана руками.** При изменении обстановки план не перестраивается.
3. **Стоимости не заданы.** План формально корректен и абсурден по времени.
4. **Перепланирование по таймеру.** Робот дёргается, задача не продвигается — нарушено разделение масштабов времени.
5. **Геометрия закодирована булевым атомом без вычисления.** Предикат `reachable` истинен всегда, план неисполним.
6. **Отказ не порождает символьного факта.** Планировщик выдаёт тот же план бесконечно.
7. **Поза перестановки выбрана без учёта последующих действий.** Объект перекладывается по три раза.
8. **Вероятности MDP взяты из пособия.** Модель описывает чужую систему; выводы к вашей не относятся.
9. **Порог уверенности не пересчитан.** Значение из семинара 1 осталось назначенным «на глаз».
