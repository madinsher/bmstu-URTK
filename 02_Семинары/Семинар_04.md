# Семинар 4. Исполнительная логика миссии

**После лекции:** 6
**Продолжительность:** 2 академических часа

## Цель

Реализовать логику миссии деревом поведения в Webots, обеспечить приоритет защитного слоя структурно, реализовать контракты навыков полностью — включая корректное прерывание — и проверить реактивность экспериментом.

## Что должно получиться

1. Работающая миссия в Webots: «обследовать — взять — довезти — уложить» с обработкой отказа.
2. Дерево поведения с защитным слоем в левейших ветвях.
3. Узлы-действия с реализованным методом прерывания.
4. Протокол трёх обязательных тестов: реактивность, прерываемость, исчерпание ветвей.
5. Сравнение с реализацией на иерархическом автомате.

## Инструменты

- **$\text{py_trees}$** (Python) — основной вариант.
- **BehaviorTree.CPP + Groot** — для команд, работающих на C++.
- **SMACH** — для сравнительной реализации (задание 5).

## Задание 1. Проектирование структуры (25 мин)

**1.1.** Постройте дерево поведения миссии. Обязательная структура корневого узла:

```
?  Корень (Fallback, memory=False)
├── →  [Слой безопасности]      ← левейшая ветвь
├── →  [Слой энергии/ресурсов]
├── →  [Миссия]
└── □  [Заведомо успешная ветвь: безопасное состояние, ожидание оператора]
```

**1.2.** Обоснуйте порядок ветвей ссылкой на теорему 6.1: приоритет обеспечивается положением узла, и гарантия не зависит от корректности рабочих ветвей.

**1.3.** Самая правая ветвь корневого Fallback должна быть **заведомо успешной**. Без неё поведение системы при исчерпании всех вариантов не определено.

**1.4.** Для каждой пары соседних узлов в Sequence проверьте условие теоремы 6.2: сохраняется ли постусловие первого при выполнении второго? Составьте таблицу:

| Sequence | Первый узел | post | Второй узел | Нарушает post? |
|---|---|---|---|---|

Найденные нарушения — потенциальные бесконечные циклы. Устраните их либо ужесточением условия завершения, либо ослаблением проверки с гистерезисом.

## Задание 2. Реализация контрактов навыков (35 мин)

**2.1.** Реализуйте не менее трёх навыков из семинара 1. Отображение контракта на структуру дерева:

| Поле контракта | Реализация |
|---|---|
| `pre` | узлы-условия в начале Sequence |
| `inv` | охраняющая ветвь слева в Fallback |
| `post` | узел-условие в конце Sequence |
| `timeout` | декоратор `Timeout` |
| `recovery` | декоратор `Retry` и/или альтернативная ветвь |
| `cancel` | метод `terminate()` узла-действия |

**2.2.** Пример структуры навыка захвата:

```
◇ Retry(2)
└── →  Sequence (memory=True)
    ├── ○  pre: припаркован у стола
    ├── ○  pre: захват пуст
    ├── ○  pre: уверенность(o) ≥ порог
    ├── □  УточнитьПозу
    ├── ◇  Timeout(12 c)
    │   └── □  СомкнутьЗахват(F ≤ 30 Н)
    └── ○  post: датчик наличия активен
```

**2.3. Метод прерывания обязателен.** Реализуйте `terminate()` для каждого узла-действия так, чтобы при прерывании система оказывалась в **определённом** состоянии:

```python
def terminate(self, new_status):
    if new_status == py_trees.common.Status.INVALID:
        self.gripper.open()
        self.arm.move_to(STOW_POSE)
        self.base.stop()
```

Прерывание «просто остановить» не принимается: манипулятор остаётся в произвольном положении, захват в неопределённом.

**2.4. Использование памяти.** Каждое `memory=True` документируется: почему повторная проверка невозможна или недопустимо дорога. Узлы верхнего уровня должны иметь `memory=False`, иначе реактивность разрушается.

## Задание 3. Три обязательных теста (30 мин)

**Тест 1. Реактивность.** Во время выполнения навыка захвата установите флаг аварийного останова (программно либо через интерфейс Webots). Требование: управление перехвачено **на следующем тике**, не позже.

Зафиксируйте: момент установки флага, момент перехвата, число тиков между ними.

**Тест 2. Прерываемость.** Прервите каждое действие на каждой фазе выполнения (начало, середина, завершение). Требование: после прерывания система в определённом состоянии — манипулятор в транспортном положении, захват раскрыт, база остановлена.

Заполните таблицу:

| Действие | Фаза прерывания | Состояние после | Соответствует cancel? |
|---|---|---|---|

**Тест 3. Исчерпание ветвей.** Создайте условия, при которых все ветви возвращают Failure (например, все предметы недостижимы, аккумулятор разряжен, зарядная станция занята). Требование: система переходит в безопасное состояние и оповещает оператора, а не «зависает» с неопределённым поведением.

## Задание 4. Отказные сценарии (20 мин)

Реализуйте и проверьте обработку не менее четырёх отказов:

| Отказ | Ожидаемое поведение |
|---|---|
| Срыв захвата | 2 повтора, затем пометка «недоступен», продолжение миссии |
| Предмет недостижим | пометка, продолжение — требование R3 из семинара 1 |
| Потеря данных камеры | переход в ожидание, оповещение |
| Разряд аккумулятора | завершение текущего навыка, возврат на базу |

Для каждого зафиксируйте: как отказ внесён, как обнаружен, какова реакция, за какое время.

**Проверьте требование R3 явно:** после исчерпания попыток по одному предмету миссия должна продолжаться с остальными, а не останавливаться.

## Критерии приёмки

| Критерий | Требование |
|---|---|
| Миссия | работает в Webots от пуска до возврата на базу |
| Структура | защитный слой левейший, самая правая ветвь заведомо успешна |
| Инвариантность | таблица пар в Sequence заполнена, нарушения устранены |
| Контракты | $\ge 3$ навыка, все семь полей реализованы |
| Прерывание | `terminate()` у каждого действия, приводит в определённое состояние |
| Память | каждое `memory=True` обосновано |
| Тест реактивности | перехват на следующем тике, зафиксировано |
| Тест прерываемости | все действия × все фазы, таблица заполнена |
| Тест исчерпания | безопасное состояние, а не зависание |
| Отказы | $\ge 4$ сценария, R3 проверено явно |
| Сравнение | таблица метрик, измеренная трудоёмкость правки |

## Типовые замечания

1. **Защитная ветвь правее рабочей.** Приоритет не обеспечен; теорема 6.1 не применима.
2. **`memory=True` на корневом узле.** Дерево перестаёт реагировать на изменение условий; тест реактивности провалится.
3. **`terminate()` не реализован.** При переключении ветви робот остаётся в неопределённом состоянии — самая частая причина повреждения оснастки.
4. **Тяжёлое условие.** Узел-условие, запускающий планировщик или обработку изображения, выполняется на каждом тике и обрушивает частоту. Условия читают переменные.
5. **Нет заведомо успешной правой ветви.** Поведение при исчерпании не определено.
6. **Бесконечный цикл подъезд — захват.** Нарушено условие инвариантности теоремы 6.2; исправление не в увеличении таймаута.
7. **Отказ приводит к остановке миссии.** Требование R3 не выполнено: предмет должен помечаться недоступным, миссия — продолжаться.
