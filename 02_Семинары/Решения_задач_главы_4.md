## Задача 4.1. Сеть ячейки и матрица инцидентности

Принятая трактовка: буфер на две позиции стоит между конвейером и роботом (конвейер → буфер → робот → станок → робот → выходной стол). Чтобы у сети были $T$-инварианты, цикл замкнут: разгрузка стола возвращает паллету на конвейер.

| Позиция | Смысл | $M_0$ |
|---|---|---|
| `p_in` | детали на конвейере | 3 |
| `p_b` | детали в буфере | 0 |
| `p_bf` | свободные места буфера | 2 |
| `p_r` | робот свободен | 1 |
| `p_s` | станок свободен | 1 |
| `a1` | робот несёт деталь буфер → станок | 0 |
| `a2` | станок обрабатывает | 0 |
| `a3` | робот несёт деталь станок → стол | 0 |
| `p_out` | детали на столе | 0 |

| Переход | Действие | Входы | Выходы |
|---|---|---|---|
| `t1` | конвейер кладёт деталь в буфер | `p_in`, `p_bf` | `p_b` |
| `t2` | робот берёт из буфера | `p_b`, `p_r` | `a1`, `p_bf` |
| `t3` | робот загружает станок | `a1`, `p_s` | `a2`, `p_r` |
| `t4` | обработка окончена, робот забирает | `a2`, `p_r` | `a3`, `p_s` |
| `t5` | робот кладёт на стол | `a3` | `p_out`, `p_r` |
| `t6` | стол разгружен, деталь на конвейере | `p_out` | `p_in` |

Матрица инцидентности $9 \times 6$:

```
         t1  t2  t3  t4  t5  t6
p_in     -1   0   0   0   0   1
p_b       1  -1   0   0   0   0
p_bf     -1   1   0   0   0   0
p_r       0  -1   1  -1   1   0
p_s       0   0  -1   1   0   0
a1        0   1  -1   0   0   0
a2        0   0   1  -1   0   0
a3        0   0   0   1  -1   0
p_out     0   0   0   0   1  -1
```

## Задача 4.2. $P$-инварианты

Алгоритм Фаркаша даёт четыре минимальных неотрицательных инварианта:

| Инвариант | Закон сохранения |
|---|---|
| $M(p_b) + M(p_{bf}) = 2$ | число мест в буфере постоянно |
| $M(p_r) + M(a_1) + M(a_3) = 1$ | робот один: свободен либо несёт деталь |
| $M(p_s) + M(a_2) = 1$ | станок один: свободен либо обрабатывает |
| $M(p_{in}) + M(p_b) + M(a_1) + M(a_2) + M(a_3) + M(p_{out}) = 3$ | детали не появляются и не исчезают |

**Буфер не переполняется.** По следствию 4.1 для инварианта $y = (0,1,1,0,\ldots)$: $M(p_b) \le \lfloor y^T M_0 / y(p_b) \rfloor = \lfloor 2/1 \rfloor = 2$ во всех достижимых маркировках. Второй и третий инварианты — взаимное исключение по следствию 4.2: робот и станок используются не более чем одной деталью каждый.

## Задача 4.3. $T$-инварианты

$C x = 0$ имеет единственное минимальное неотрицательное решение $x = (1,1,1,1,1,1)$: один технологический маршрут, каждая операция срабатывает по разу за цикл, все шесть переходов покрыты. По следствию 4.3 необходимое условие повторяемости выполнено.

**Что стоит показать студентам сверх вопроса задачи.** Необходимое — не достаточное: граф достижимости содержит 30 маркировок и **один тупик** $M(p_b) = 1, M(p_{bf}) = 1, M(a_1) = 1, M(a_2) = 1$. Робот взял из буфера вторую деталь, пока станок занят; разгрузить станок (`t4`) может только робот, а он держит деталь и ждёт станок (`t3`). Причина по теореме 4.5 — сифон $\lbrace a_3, p_r, p_s \rbrace$, у которого нет помеченной ловушки (остальные четыре минимальных сифона — носители $P$-инвариантов и опустеть не могут). Инварианты доказали ограниченность и взаимное исключение, но не живость. Лечение — монитор задачи 4.5: $M(a_1) + M(a_2) \le 1$ (робот берёт из буфера, только если станок свободен), $M_0(V) = 1$, $C_V = (0, -1, 0, +1, 0, 0)$: разрешение забирается на `t2` и возвращается на `t4`. После этого 27 состояний, тупиков нет, сеть жива и обратима; 27 — это ровно все состояния исходной сети, из которых достижима $M_0$, то есть монитор максимально разрешителен.

## Задача 4.4. Минимальные сифоны примера 4.6.4

Сеть: `p10 →t1(rM)→ a1 →t2(rZ)→ a2 →t3→ p10 + rM + rZ`, `p20 →t4(rZ)→ b1 →t5(rM)→ b2 →t6→ p20 + rM + rZ`; $M_0$: по одному заданию в `p10`, `p20`, ресурсы `rM`, `rZ` по одному.

Полный перебор подмножеств позиций (255 подмножеств) даёт пять минимальных сифонов:

| Сифон | $M_0(S)$ | Ловушка внутри | Вывод |
|---|---|---|---|
| $\lbrace p_{10}, a_1, a_2 \rbrace$ | 1 | сам сифон — ловушка (носитель инварианта процесса 1) | безопасен |
| $\lbrace p_{20}, b_1, b_2 \rbrace$ | 1 | то же, процесс 2 | безопасен |
| $\lbrace r_M, a_1, a_2, b_2 \rbrace$ | 1 | ресурсный инвариант $r_M$ | безопасен |
| $\lbrace r_Z, a_2, b_1, b_2 \rbrace$ | 1 | ресурсный инвариант $r_Z$ | безопасен |
| $\lbrace r_M, r_Z, a_2, b_2 \rbrace$ | 2 | **максимальная ловушка внутри пуста** | опасен |

Проверка сифонности «плохого» множества по определению 4.3: $\bullet S = \lbrace t_2, t_3, t_5, t_6 \rbrace$ (переходы, кладущие в $a_2, b_2, r_M, r_Z$), $S\bullet = \lbrace t_1, t_2, t_3, t_4, t_5, t_6 \rbrace$; включение выполнено. Ловушкой оно не является: $t_1 \in S\bullet$ берёт из $r_M$, но ничего в $S$ не кладёт. Сифон опустошается ровно в одной достижимой маркировке из шести — в тупике $M^{*}$: $M(a_1) = M(b_1) = 1$. Это единственный строгий минимальный сифон, и по теореме 4.8 система не жива.

## Задача 4.5. Место-монитор

Ресурсы сифона: $r_M$ с держателями $H(r_M) = \lbrace a_1, a_2, b_2 \rbrace$ и $r_Z$ с $H(r_Z) = \lbrace a_2, b_1, b_2 \rbrace$. Ограничивать надо позиции, которые держат ресурс сифона, но в сифон не входят: $[S] = \lbrace a_1, b_1 \rbrace$. Ограничение

$$M(a_1) + M(b_1) \le M_0(S) - 1 = 1,$$

то есть $l = (0,1,0,0,1,0,0,0)$ по порядку `p10 a1 a2 p20 b1 b2 rM rZ`, $\beta = 1$. По теореме 4.9:

- $M_0(V) = \beta - l^T M_0 = 1 - 0 = 1$;
- $l^T C = (+1, -1, 0, +1, -1, 0)$, значит $C_V = -l^T C = (-1, +1, 0, -1, +1, 0)$: дуги $V \to t_1$, $t_2 \to V$, $V \to t_4$, $t_5 \to V$.

Смысл: $V$ — единственное разрешение «держать один ресурс, ожидая второго». Расширенная сеть: 5 достижимых маркировок (было 6, ушёл тупик), тупиков нет, все переходы живы, сеть обратима. Появился новый сифон $\lbrace V, a_1, b_1 \rbrace$ — носитель инварианта $M(a_1) + M(b_1) + M(V) = 1$, безопасен; плохой сифон $\lbrace r_M, r_Z, a_2, b_2 \rbrace$ теперь ни в одной маркировке не пуст.

**Типовая ошибка** (проверено): ограничение на сами позиции сифона $M(a_2) + M(b_2) \le 1$ тупик не устраняет — в $M^{*}$ они и так пусты. Альтернатива монитору — единый порядок захвата $(r_M, r_Z)$: процесс 2 сначала берёт робота, потом зону; тоже 5 состояний без тупиков, но это изменение технологического маршрута.

## Задача 4.6. Три процесса, три ресурса

Конфигурация с тупиком: $\pi_1$ берёт $r_1$, затем $r_2$; $\pi_2$ — $r_2$, затем $r_3$; $\pi_3$ — $r_3$, затем $r_1$ (12 позиций, 9 переходов, по одному заданию на процесс). Инварианты: три процессных и три ресурсных ($M(r_1) + M(a_1) + M(a_2) + M(c_2) = 1$ и аналогично). Достижимо 14 маркировок, один тупик: $M(a_1) = M(b_1) = M(c_1) = 1$ — каждый держит свой первый ресурс и ждёт следующего по кругу. Плохой сифон $\lbrace r_1, r_2, r_3, a_2, b_2, c_2 \rbrace$, $M_0(S) = 3$, ловушки внутри нет.

**Упорядочивание** $r_1 < r_2 < r_3$: маршруты $\pi_1, \pi_2$ уже возрастающие, $\pi_3$ должен захватывать $r_1$, затем $r_3$. Сеть с изменённым маршрутом: 12 достижимых маркировок, тупиков нет, все переходы живы. Отсутствие кругового ожидания — задача 4.8. При двух заданиях на процесс картина та же (ресурсы единичные): 14 состояний, тупик $M(a_1) = M(b_1) = M(c_1) = 1$.

## Задача 4.7. Банкирский алгоритм и сравнение с мониторами

Таблицы для стадий процессов (ресурс единичный):

| Стадия | Alloc | Need |
|---|---|---|
| $a_1$ | $r_1$ | $r_2$ |
| $a_2$ | $r_1, r_2$ | — |
| $b_1$ | $r_2$ | $r_3$ |
| $b_2$ | $r_2, r_3$ | — |
| $c_1$ | $r_3$ | $r_1$ |
| $c_2$ | $r_1, r_3$ | — |

Запрос ресурса удовлетворяется, если состояние после выдачи безопасно по алгоритму 4.2. Например, при $M(a_1) = M(b_1) = 1$ запрос $\pi_3$ на $r_3$ отклоняется: после выдачи `Available` пуст, ни у кого `Need` не покрыт. Без него $\pi_2$ завершается, освобождает $r_2$, за ней $\pi_1$, и так далее.

Результат сравнения (по одному заданию на процесс):

| Политика | Состояний | Тупиков |
|---|---|---|
| без ограничений | 14 | 1 |
| безопасные состояния (из которых достижима $M_0$) — максимум разрешительности | 13 | — |
| монитор $M(a_1) + M(b_1) + M(c_1) \le 2$ | 13 | 0 |
| банкир | 13 | 0 |
| порядок $r_1 < r_2 < r_3$ | 12 | 0 |

**Ответ на вопрос задачи:** в этой системе монитор и банкир совпадают и оба максимально разрешительны — разница 0 состояний. Единственный опасный сифон запрещает ровно одно состояние, и монитор отрезает именно его. То же при ёмкости ресурсов 2 (85 состояний, тупик $M(a_1) = M(b_1) = M(c_1) = 2$; монитор $\le 5$ и банкир дают по 84). Консервативность мониторов, о которой говорит раздел 4.7.2, проявляется, когда несколько сифонов пересекаются и ограничения на их дополнения запрещают безопасные комбинации, — здесь такого нет. Упорядочивание запрещает 4 состояния из 13, но оно меняет маршрут $\pi_3$, так что его состояния несопоставимы с остальными напрямую.

## Задача 4.8. Доказательство утверждения 4.2

Пусть на ресурсах задан полный порядок $<$ и каждый процесс, удерживая ресурс $r$, запрашивает только ресурсы $r' > r$. Допустим, возникло круговое ожидание: процессы $\pi_1, \ldots, \pi_k$ ($k \ge 2$), $\pi_i$ удерживает $r_i$ и ждёт $r_{i+1}$, а $\pi_k$ ждёт $r_1$. По правилу захвата $r_i < r_{i+1}$ для $i = 1, \ldots, k-1$ и $r_k < r_1$. Транзитивность даёт $r_1 < r_1$ — противоречие с антирефлексивностью строгого порядка. Значит, цикла ожидания нет. Случай $k = 1$ невозможен: процесс не ждёт ресурс, который сам держит.

Нарушается **четвёртое условие Коффмана — круговое ожидание**; первые три (взаимное исключение, удержание и ожидание, отсутствие вытеснения) сохраняются. Тупик по теореме о четырёх условиях невозможен, что и подтверждает граф достижимости упорядоченной сети (12 состояний, тупиков нет).

## Задача 4.9. Полная ячейка примера Б

**Шаг 1. Сеть.** Ресурсы: $M_1$, $M_2$, станок $S$, зона $Z$, буфер $B$ (ёмкость 2), AMR. Два маршрута.

Маршрут A (через станок): `pA0 →tA1(M1)→ a1 →tA2(Z)→ a2 →tA3(S; освобождает M1, Z)→ a3 →tA4(M2, Z)→ a4 →tA5(B; освобождает S, M2, Z)→ a5 →tA6(AMR; освобождает B)→ a6 →tA7(освобождает AMR)→ pA0`.

Маршрут B (без станка): `pB0 →tB1(M2)→ b1 →tB2(Z)→ b2 →tB3(B; освобождает M2, Z)→ b3 →tB4(AMR; освобождает B)→ b4 →tB5→ pB0`.

$M_0$: 2 паллеты A, 1 паллета B, все ресурсы свободны. 18 позиций, 12 переходов.

**Шаги 2–3. $P$-инварианты** — восемь, по одному на ресурс и на маршрут:

| Инвариант | Доказывает |
|---|---|
| $M(M_1) + M(a_1) + M(a_2) = 1$ | $M_1$ занят одной деталью |
| $M(M_2) + M(a_4) + M(b_1) + M(b_2) = 1$ | $M_2$ — взаимное исключение маршрутов A и B |
| $M(S) + M(a_3) + M(a_4) = 1$ | станок |
| $M(Z) + M(a_2) + M(a_4) + M(b_2) = 1$ | зона эксклюзивна (требование R1 примера Б) |
| $M(B) + M(a_5) + M(b_3) = 2$ | буфер не переполняется: $M(a_5) + M(b_3) \le 2$ |
| $M(AMR) + M(a_6) + M(b_4) = 1$ | AMR везёт одну деталь |
| $\sum$ по маршруту A $= 2$, по маршруту B $= 1$ | детали не теряются |

**Шаг 4. $T$-инварианты:** два — `tA1…tA7` и `tB1…tB5`, по одному на маршрут; все переходы покрыты.

**Шаг 5. Сифоны.** Девять минимальных; восемь — носители инвариантов. Единственный опасный: $S_1 = \lbrace S, Z, a_4, b_2 \rbrace$, $M_0(S_1) = 2$, ловушки внутри нет. Граф достижимости: 81 маркировка, один тупик

$$M(a_2) = 1,\ M(a_3) = 1,\ M(b_1) = 1$$

— $M_1$ стоит в зоне с деталью и ждёт станок; станок закончил и ждёт $M_2$ с зоной; $M_2$ держит деталь B и ждёт зону. Три единицы оборудования ждут друг друга по кругу, сифон $S_1$ пуст.

**Шаг 6. Ограничение.** Держатели ресурсов сифона вне его: $[S_1] = \lbrace a_2, a_3 \rbrace$ ($a_4, b_2 \in S_1$ не считаются). Монитор $V_1$: $M(a_2) + M(a_3) \le 1$, $M_0(V_1) = 1$; $l^T C$ отличен от нуля только в столбцах `tA2` ($+1$) и `tA4` ($-1$), поэтому $C_{V_1} = -l^T C$ даёт дуги $V_1 \to tA2$ и $tA4 \to V_1$: разрешение забирается при входе $M_1$ в зону и возвращается, когда $M_2$ выгрузил станок. Технологический смысл: **$M_1$ входит в зону с деталью, только если станок свободен**.

**Шаг 7. Повторный анализ.** Расширенная сеть: 77 маркировок, тупиков 0, все 12 переходов живы, обратима. Новый сифон $\lbrace V_1, a_2, a_3 \rbrace$ — носитель инварианта, безопасен; $S_1$ больше не опустошается. Монитор максимально разрешителен: 77 — это в точности число состояний исходной сети, из которых достижима $M_0$. Проверено также для больших маркировок: (3 A, 2 B, буфер 2) — 227 состояний, 1 тупик, после монитора 207 = все безопасные; (4 A, 3 B, буфер 2) — 308 → 275; (3 A, 2 B, буфер 1) — 146 → 131. Одного монитора хватает при всех проверенных маркировках.

**Шаг 8. Остаточные риски.**
- Анализ выполнен для конкретных маркировок; для $S^3PR$-подобной структуры сифон $S_1$ единственный при любых $n$, но это проверено перебором, а не доказано.
- Маршрут B не может ждать буфера в зоне бесконечно только потому, что AMR всегда возвращается; отказ AMR модель не содержит.
- Освобождение $M_1$ и $Z$ одновременно с загрузкой станка (`tA3`) — упрощение: если разнести эти события, появляется промежуточная позиция и анализ надо повторить.
- Живость доказана для модели без отказов оборудования; отказы добавляются на этапе 5 семинарского проекта.
