# Семинар 3. Сеть Петри ячейки: структурный анализ и производительность

**После лекций:** 4–5
**Продолжительность:** 2 академических часа

## Цель

Построить сеть Петри ячейки, доказать свойства безопасности инвариантами, найти структурную причину возможного тупика, синтезировать беступиковую политику и получить количественную оценку производительности с кривой насыщения.

## Что должно получиться

1. Сеть Петри с проверенными P- и $T$-инвариантами.
2. Доказательства ограниченности буфера и взаимного исключения.
3. Список минимальных сифонов с проверкой на помеченную ловушку.
4. Синтезированная беступиковая политика и повторный анализ.
5. Кривая насыщения по критическому ресурсу.
6. Имитационная проверка с доверительными интервалами.

## Инструменты

- **PIPE** — редактор и анализатор сетей Петри, вычисление инвариантов.
- Собственная реализация поиска сифонов на Python — обязательна.
- **SimPy** — имитационное моделирование.

## Задание 1. Построение сети (20 мин)

**1.1.** Постройте сеть по технологическому маршруту:
- каждой операции — операционная позиция;
- каждому переходу между операциями — переход сети;
- каждому ресурсу — ресурсная позиция с ёмкостью $C(r)$;
- каждому процессу — позиция простоя с начальным запасом заданий.

**1.2.** Выпишите матрицу инцидентности $C = C^+ - C^-$.

**1.3.** Задайте начальную маркировку, соответствующую **реальному пуску** ячейки, а не удобному примеру.

## Задание 2. Инварианты и свойства безопасности (25 мин)

**2.1.** Вычислите все минимальные $P$-инварианты (PIPE либо алгоритм Фаркаша).

**2.2.** Для каждого ресурса проверьте наличие ожидаемого инварианта сохранения вида

```math
M(r) + \sum_{p \in H(r)} M(p) = C(r)
```

**Отсутствие такого инварианта означает ошибку моделирования** — ресурс где-то теряется или размножается. Это первая и самая дешёвая проверка модели, выполните её до всего остального.

**2.3.** Докажите ограниченность буфера, выписав применение следствия $4.1: M(p) \le \lfloor y^TM_0 / y(p)\rfloor$.

**2.4.** Докажите взаимное исключение по зоне (или другому эксклюзивному ресурсу): найдите инвариант с суммой, равной 1, и приведите рассуждение о том, что не более одного слагаемого может быть единицей.

**2.5.** Вычислите $T$-инварианты. Проверьте:
- каждый минимальный $T$-инвариант соответствует одному технологическому маршруту;
- все переходы покрыты хотя бы одним неотрицательным $T$-инвариантом.

Непокрытый переход — либо одноразовая инициализация, либо ошибка. Разберитесь, какой из вариантов ваш.

## Задание 3. Сифоны и тупики (30 мин)

**3.1.** Реализуйте проверку условия сифона:

```python
def is_siphon(net, S):
    """S — множество позиций. Условие: •S ⊆ S•"""
    pre_S  = {t for p in S for t in net.pre_of_place(p)}
    post_S = {t for p in S for t in net.post_of_place(p)}
    return pre_S <= post_S
```

**3.2.** Найдите все минимальные сифоны перебором (для сети до 15 позиций перебор допустим).

**3.3.** Для каждого сифона проверьте, содержит ли он помеченную при $M_0$ ловушку. Сифон с помеченной ловушкой безопасен по теоремам 4.4 и 4.6.

**3.4.** Для сифонов без помеченной ловушки постройте достижимую маркировку, при которой сифон пуст. Опишите соответствующий сценарий тупика словами: какие ресурсы исчерпались совместно и почему.

**Если в вашей сети опасных сифонов не нашлось** — усложните модель. Введите второй процесс, захватывающий те же ресурсы в противоположном порядке. Тупик должен появиться; это упражнение обязательно.

## Задание 4. Синтез беступиковой политики (25 мин)

Реализуйте **два** из трёх методов и сравните.

**4.1. Места-мониторы.** Для опасного сифона $S$ наложите ограничение $\sum_{p \in S_A} M(p) \le M_0(S) - 1$. Постройте монитор по теореме 4.9:

```math
M_0(V) = \beta - l^TM_0, \quad C_V = -l^TC
```

Проверьте, что тупик устранён, и **выполните повторный анализ**: добавление монитора меняет структуру и может породить новые сифоны.

**4.2. Упорядочивание ресурсов.** Введите полный порядок и потребуйте захвата в возрастающем порядке. Докажите отсутствие кругового ожидания. Укажите, какое изменение технологического маршрута при этом требуется и с кем оно должно быть согласовано.

**4.3. Банкирский алгоритм.** Реализуйте проверку безопасности состояния и включите её в захват ресурсов.

**4.4. Сравнение.** Для каждого реализованного метода определите множество разрешённых состояний. Насколько мониторы консервативнее банкира? Приведите конкретное состояние, разрешённое банкиром и запрещённое монитором.

## Задание 5. Количественная оценка (30 мин)

**5.1. Граница по узкому месту.** Составьте таблицу длительностей операций и занятости ресурсов за один цикл. Вычислите

```math
\Theta \le 1 / \max_r (\tau(r) / C(r))
```

Укажите узкое место.

**5.2. Точное время цикла (max-plus).** Постройте граф зависимостей операций с учётом ресурсных ограничений. Реализуйте алгоритм Карпа и найдите максимальный средний вес цикла. Выведите критический цикл.

Сравните с оценкой 5.1. Если результаты различаются — объясните, что учёл max-plus и не учла простая граница.

**5.3. Кривая насыщения.** Пересчитайте время цикла для 1, 2, 3, 4, 5 экземпляров критического ресурса. Постройте таблицу и график. Определите, при каком числе экземпляров узкое место смещается и дальнейшие вложения перестают давать выигрыш.

Это основной документ для обоснования состава оборудования — оформите его аккуратно.

**5.4. Учёт отказов.** Постройте GSPN или марковскую модель для критического ресурса с отказами и ремонтом. Найдите стационарное распределение, вычислите пропускную способность. Сравните с детерминированной оценкой; типичное расхождение 20–35 %.

## Критерии приёмки

| Критерий | Требование |
|---|---|
| Инварианты | найдены, для каждого ресурса есть закон сохранения |
| Безопасность | ограниченность и взаимное исключение доказаны, а не проверены прогоном |
| $T$-инварианты | все переходы покрыты, маршруты идентифицированы |
| Сифоны | все минимальные найдены, проверены на помеченную ловушку |
| Тупик | найден, сценарий описан словами |
| Политика | два метода реализованы и сравнены по разрешительности |
| Повторный анализ | выполнен после введения мониторов |
| Производительность | граница, max-plus, кривая насыщения, учёт отказов |
| Статистика | доверительные интервалы, проверка закона Литтла |

## Типовые замечания

1. **Ожидаемый инвариант не найден, и это не проверено.** Первая проверка модели пропущена.
2. **Начальная маркировка «для примера».** Выводы относятся к несуществующей конфигурации.
3. **Сифоны найдены, но не проверены на ловушку.** Половина работы: сифон с помеченной ловушкой безопасен.
4. **Мониторы добавлены, повторный анализ не выполнен.** Новые сифоны не обнаружены.
5. **Кривая насыщения не построена.** Главный практический артефакт занятия отсутствует.
6. **Вывод «вторая конфигурация лучше» без интервала.** Не принимается.
7. **max-plus не выполнен, взята только простая граница.** Разница между 22 и 32 секундами — 45 % производительности.
