# Семинар 7. Второй робот: координация и расписание

**После лекций:** 13–14
**Продолжительность:** 2 академических часа

## Цель

Ввести в проект второго активного исполнителя, распределить между роботами задачи, обеспечить бесконфликтное движение в общей зоне, построить расписание и убедиться, что оно исполнимо при реальном разбросе длительностей.

## Что должно получиться

1. Реализованное распределение задач с сравнением централизованного и жадного вариантов.
2. Бесконфликтные маршруты (CBS) и робастное исполнение через временной граф плана.
3. Проверенная пропускная способность узкого места маршрутной сети.
4. Сеть Петри схемы резервирования с найденными сифонами и монитором направления.
5. Расписание в CP-SAT с нижними оценками и диаграммой Гантта.
6. Сценарий отказа робота с переназначением задач.

## Инструменты

- **OR-Tools CP-SAT** — расписание.
- Собственная реализация венгерского алгоритма и CBS.
- **SimPy** — проверка робастности расписания.

## Задание 1. Ввод второго робота (15 мин)

**1.1.** Добавьте в сцену второго активного исполнителя: второй мобильный робот (вариант А) либо второй манипулятор и AMR (вариант Б).

**1.2.** Определите разделяемые ресурсы: узкий проход, зона перегрузки, станок, зарядная станция.

**1.3.** Определите, какие задачи может выполнять каждый робот. Если возможности различаются, зафиксируйте матрицу «робот × тип задачи».

## Задание 2. Распределение задач (30 мин)

**2.1.** Определите класс вашей задачи по таксономии MRTA: ST/MT, SR/MR, IA/TA. Обоснуйте.

**2.2.** Постройте матрицу стоимостей $c_{ij}$ — время выполнения задачи $j$ роботом $i$, включая переезд из текущего положения.

**2.3.** Реализуйте венгерский алгоритм и решите задачу назначения. Реализуйте также жадное назначение.

**2.4.** Сравните на 100 случайных матрицах: постройте распределение относительного проигрыша жадного метода. Насколько велик разброс?

**2.5.** Реализуйте вариант с критерием **минимакса** (бинарный поиск по порогу с проверкой существования паросочетания). Сравните решения по обоим критериям на одной матрице. Какой критерий уместнее для вашей задачи и почему?

**2.6.** *Дополнительно.* Реализуйте последовательный жадный аукцион или CBBA. Сравните качество с централизованным решением и оцените число сообщений.

## Задание 3. Пропускная способность маршрутной сети (15 мин)

**3.1.** Постройте маршрутную сеть: вершины — позиции, рёбра — переходы. Выделите узкие места (перекрёстки, коридоры) в отдельные секции.

**3.2.** Для узкого места вычислите пропускную способность: 1 / время занятия. Сопоставьте с требуемой интенсивностью потока.

**3.3.** **Если сеть перегружена — дальнейшая оптимизация координации бессмысленна.** Зафиксируйте вывод и предложите решение: второй проход, сокращение времени проезда, изменение планировки.

Этот расчёт выполняется **до** реализации алгоритмов координации, а не после.

## Задание 4. Бесконфликтные маршруты (30 мин)

**4.1.** Реализуйте приоритетное планирование: агенты планируются по очереди, уже спланированные пути — динамические препятствия.

**4.2.** Постройте сцену, на которой приоритетное планирование терпит неудачу, а решение существует (узкий проход, обмен местами, один карман-разъезд). Продемонстрируйте отказ.

**4.3.** Реализуйте CBS: верхний уровень — поиск по дереву ограничений, нижний — A\* по паре (вершина, время).

**4.4.** Убедитесь, что CBS находит решение на сцене из 4.2.

**4.5.** Измерьте время решения как функцию числа агентов (2–8) на вашей сети. Постройте график.

**4.6.** Явно перечислите, какие типы конфликтов запрещены в вашей реализации: вершинный, рёберный, следования. Конфликт следования допустим в классической постановке, но недопустим для реальных роботов с габаритом и инерцией.

## Задание 5. Робастное исполнение (20 мин)

**5.1.** Постройте временной граф плана (TPG): вершины — события «агент прибыл в вершину», дуги маршрута и дуги приоритета.

**5.2.** Проверьте ацикличность топологической сортировкой.

**5.3.** Реализуйте исполнение по TPG: агент входит в вершину только после того, как предшественник по дуге приоритета её покинул.

**5.4.** **Тест робастности.** Задержите одного агента на 3–5 тактов (программно либо препятствием). Убедитесь, что исполнение остаётся бесконфликтным, а задержка распространяется как ожидание.

**5.5.** **Тест правки.** Внесите отклонение от плана (агент объехал по другой вершине). Проверьте TPG на ацикличность. Постройте пример, в котором цикл возникает, и покажите, что это тупик.

## Задание 6. Резервирование и тупики (20 мин)

**6.1.** Постройте сеть Петри схемы резервирования секций маршрутной сети.

**6.2.** Найдите минимальные сифоны (используйте реализацию семинара 3). Есть ли опасные?

**6.3.** Для двустороннего узкого прохода покажите тупик при встречном движении. Структурно это конфигурация из главы 4: захват в противоположных порядках.

**6.4.** Реализуйте **монитор направления**: въезд разрешается только в текущем направлении, направление меняется при отсутствии желающих ехать в нём.

**6.5. Проверка на голодание.** Подайте постоянный поток в одну сторону. Убедитесь, что встречные роботы не голодают — введите дисциплину чередования. Это то же свойство живости, которое проверялось в NuSMV на семинаре 5.

## Задание 7. Расписание (25 мин)

**7.1.** Сформулируйте задачу цехового планирования (или гибкого, если операция может выполняться разными роботами) в OR-Tools CP-SAT: интервальные переменные, `AddNoOverlap` для ресурсов, `AddCumulative` для ресурсов ёмкости $k$.

**7.2.** Вычислите нижние оценки $\mathrm{LB}_1$ (по ресурсу), $\mathrm{LB}_2$ (по заданию), $\mathrm{LB}_3$ (с головами и хвостами).

**7.3.** Решите задачу. Зафиксируйте: найденный макспан, нижнюю оценку, **разрыв оптимальности** от решателя.

**7.4.** Постройте диаграмму Гантта.

**7.5.** Определите критический путь. Какие операции его образуют? Сокращение каких операций не даст ничего?

**7.6.** Добавьте один экземпляр критического ресурса и пересчитайте. Постройте таблицу «число экземпляров → макспан» — это обоснование состава оборудования.

**7.7.** Сравните с расписанием по правилам SPT, EDD и MWKR. Насколько правила хуже оптимума?

## Задание 8. Отказ и перепланирование (15 мин)

**8.1.** Смоделируйте отказ одного робота на 30 % выполнения плана.

**8.2.** Реализуйте три стратегии: сдвиг вправо, частичное перепланирование, полный пересчёт. Сравните по макспану и по числу изменённых моментов начала.

**8.3. Стабильность.** Добавьте в целевую функцию штраф за отклонение от прежнего расписания: $\min [\alpha \cdot C_{\max} + \beta \cdot \Sigma \lvert s^{\mathrm{new}} - s^{\mathrm{old}}\rvert]$. Подберите $\beta$ так, чтобы расписание не перестраивалось целиком при малом возмущении.

**8.4.** Проверьте связность маршрутной сети при блокировке отказавшим роботом каждой секции. Какие секции **критичны** — их блокировка разрезает сеть? Зафиксируйте для анализа рисков на семинаре 8.

**8.5.** Убедитесь, что задачи отказавшего робота корректно переназначены.

## Задание 9. Проверка робастности расписания (10 мин)

**9.1.** Смоделируйте исполнение расписания в SimPy при разбросе длительностей (коэффициент вариации 0,15), 50 прогонов.

**9.2.** Постройте распределение фактического макспана. Сравните с номинальным.

**9.3.** Определите, в каких точках расписание рвётся чаще всего. Именно туда следует ставить временные резервы.

## Критерии приёмки

| Критерий | Требование |
|---|---|
| Класс MRTA | определён и обоснован |
| Распределение | венгерский алгоритм реализован, сравнение с жадным на 100 матрицах |
| Критерии | сумма и минимакс сравнены, выбор обоснован |
| Пропускная способность | посчитана **до** оптимизации координации |
| Приоритетное планирование | отказ продемонстрирован на конкретной сцене |
| CBS | реализован, находит решение там, где приоритетное не находит |
| Типы конфликтов | перечислены явно |
| TPG | построен, ацикличность проверяется, тест задержки пройден |
| Цикл в TPG | продемонстрирован пример возникновения |
| Сифоны | найдены в схеме резервирования, монитор направления работает |
| Голодание | проверено при постоянном потоке в одну сторону |
| Расписание | CP-SAT, нижние оценки, разрыв, Гантт, критический путь |
| Отказ | три стратегии сравнены, критические секции найдены |
| Робастность | 50 прогонов, распределение макспана, точки разрыва |

## Типовые замечания

1. **Оптимизация координации при перегруженной сети.** Алгоритм перераспределит ожидание, но не создаст пропускной способности.
2. **Конфликт следования допущен.** Реальные роботы столкнутся, хотя план формально бесконфликтен.
3. **План исполняется по расписанию.** Первая же задержка приводит к столкновению.
4. **TPG не проверяется на ацикличность при правке.** Тупик при первом отклонении от плана.
5. **Монитор направления без чередования.** Встречные роботы голодают при постоянном потоке.
6. **Нижние оценки не посчитаны.** Неизвестно, хорошее расписание или плохое.
7. **Критические секции не выявлены.** Отказ робота в единственном коридоре останавливает комплекс, и это не предусмотрено.
8. **Расписание не проверено на робастность.** Оптимальное по номиналу расписание разваливается при реальном разбросе.
